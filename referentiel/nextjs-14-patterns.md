# Next.js 14+ Design Patterns

Comprehensive guide to Next.js 14+ patterns using App Router, Server Components, and modern React features.

**Version**: Next.js 14+
**Router**: App Router (app/ directory)

## Overview

Next.js 14+ introduces fundamental paradigm shifts:

1. **App Router** - File-system based routing with app/ directory
2. **Server Components by Default** - React Server Components (RSC)
3. **Streaming and Suspense** - Progressive rendering
4. **Server Actions** - Server-side mutations without API routes
5. **Parallel Routes** - Multiple pages rendered simultaneously
6. **Route Intercepting** - Modal-like UX patterns

**Key principle**: Server-first with client opt-in, not client-first with server opt-in.

## 1. File-Based Routing Pattern

### App Router Structure

```
app/
├── layout.tsx           # Root layout (required)
├── page.tsx             # Home page (/)
├── loading.tsx          # Loading UI for page
├── error.tsx            # Error boundary for page
├── not-found.tsx        # 404 page
├── global.css           # Global styles
├── dashboard/
│   ├── layout.tsx       # Dashboard layout
│   ├── page.tsx         # /dashboard
│   ├── loading.tsx      # Loading UI
│   ├── settings/
│   │   └── page.tsx     # /dashboard/settings
│   └── [userId]/
│       └── page.tsx     # /dashboard/123 (dynamic)
├── blog/
│   ├── [slug]/
│   │   └── page.tsx     # /blog/my-post
│   └── [...slug]/
│       └── page.tsx     # /blog/a/b/c (catch-all)
└── (marketing)/         # Route group (doesn't affect URL)
    ├── layout.tsx       # Marketing layout
    ├── about/
    │   └── page.tsx     # /about
    └── contact/
        └── page.tsx     # /contact
```

### Special Files

| File | Purpose | Required |
|------|---------|----------|
| `layout.tsx` | Shared UI for segment and children | Yes (root) |
| `page.tsx` | Unique UI of route, makes route publicly accessible | Yes |
| `loading.tsx` | Loading UI, wraps page in Suspense boundary | No |
| `error.tsx` | Error UI, wraps page/layout in Error Boundary | No |
| `not-found.tsx` | UI when `notFound()` is called or no route match | No |
| `route.ts` | API endpoint (GET, POST, etc.) | No |
| `template.tsx` | Re-rendered layout (doesn't persist state) | No |
| `default.tsx` | Fallback for parallel routes | No |

### Route Groups

**Purpose**: Organize routes without affecting URL structure.

```typescript
// app/(marketing)/layout.tsx - Marketing layout
export default function MarketingLayout({ children }: { children: React.ReactNode }) {
  return (
    <div>
      <nav>{/* Marketing nav */}</nav>
      {children}
    </div>
  )
}

// app/(dashboard)/layout.tsx - Dashboard layout
export default function DashboardLayout({ children }: { children: React.ReactNode }) {
  return (
    <div>
      <nav>{/* Dashboard nav */}</nav>
      {children}
    </div>
  )
}
```

**Benefits**:
- Different layouts without nested URLs
- Organize files by domain
- Multiple root layouts in same app

```typescript
import { Sidebar } from '@/components/Sidebar'
```

### Layout Persistence

**Layouts persist state across navigation** (don't re-render).

```typescript
// app/dashboard/layout.tsx
export default function DashboardLayout({ children }: { children: React.ReactNode }) {
  const [sidebarOpen, setSidebarOpen] = useState(true) // ✅ State persists!

  return (
    <div>
      <Sidebar open={sidebarOpen} onToggle={() => setSidebarOpen(!sidebarOpen)} />
      {children}
    </div>
  )

```

```typescript
// app/dashboard/template.tsx

  const [state] = useState() // ❌ State resets on navigation
  return <div>{children}</div>
}
```

## 3. Server Components vs. Client Components

### Default: Server Components

**All components in app/ are Server Components by default.**

```typescript
// app/blog/page.tsx - Server Component (default)
async function BlogPage() {
  const posts = await db.post.findMany() // ✅ Direct DB access

  return (
    <div>
      {posts.map(post => (
        <article key={post.id}>{post.title}</article>
      ))}
    </div>
  )
}
```

**Benefits**:
- Zero JavaScript sent to client
- Direct database/API access
- Keep sensitive data on server (API keys, tokens)
- Large dependencies stay on server
- Faster initial page load

**Limitations**:
- ❌ No `useState`, `useEffect`, or React hooks
- ❌ No browser APIs (localStorage, window)
- ❌ No event handlers (onClick, onChange)
- ❌ No Context providers

### Client Components: Opt-In

**Use `'use client'` directive** at the top of file:

```typescript
// components/Counter.tsx - Client Component
'use client'

import { useState } from 'react'

export function Counter() {
  const [count, setCount] = useState(0)

  return (
    <button onClick={() => setCount(count + 1)}>
      Count: {count}
    </button>
  )
}
```

**When to use Client Components**:
- Need React hooks (useState, useEffect, useContext)
- Need event handlers (onClick, onSubmit)
- Need browser APIs (localStorage, window, navigator)
- Need third-party libraries that use React hooks
- Need real-time updates (WebSocket, subscriptions)

### Composition Pattern

**Keep Server Components at the top**, pass Client Components as children:

```typescript
// app/page.tsx - Server Component
import { ClientSidebar } from '@/components/ClientSidebar'

async function HomePage() {
  const data = await fetchData() // Server data

  return (
    <div>
      {/* ✅ Server Component - no JS */}
      <header>
        <h1>{data.title}</h1>
      </header>

      {/* ❌ Client Component - sends JS */}
      <ClientSidebar />
    </div>
  )
}
```

**Better: Server Component wrapper**:

```typescript
// app/page.tsx - Server Component
import { Sidebar } from '@/components/Sidebar'
import { InteractiveWidget } from '@/components/InteractiveWidget'

async function HomePage() {
  const data = await fetchData()
  const widgetData = await fetchWidgetData()

  return (
    <Sidebar> {/* Server Component */}
      <InteractiveWidget data={widgetData} /> {/* Client Component inside */}
    </Sidebar>
  )
}
```

```typescript
// components/Sidebar.tsx - Server Component (default)
export function Sidebar({ children }: { children: React.ReactNode }) {
  return (
    <aside className="sidebar">
      {/* Static content - no JS */}
      <nav>...</nav>
      {children}
    </aside>
  )
}
```

```typescript
// components/InteractiveWidget.tsx - Client Component
'use client'

export function InteractiveWidget({ data }: { data: any }) {
  const [expanded, setExpanded] = useState(false)
  return <div onClick={() => setExpanded(!expanded)}>...</div>
}
```

### Decision Tree: Server or Client?

```
Does component need interactivity (onClick, useState, etc.)?
├─ No → Server Component (default)
│   └─ Benefits: No JS, direct DB access, server-only code
└─ Yes → Client Component ('use client')
    ├─ Can you move interactivity to a child component?
    │   ├─ Yes → Keep parent as Server Component
    │   └─ No → Make this a Client Component
    └─ Does it need data from server?
        ├─ Yes → Fetch in Server Component, pass as prop
        └─ No → Fetch client-side in useEffect/SWR
```

### Sharing Data Between Server Components

**Don't pass data through props**, use fetch with caching:

```typescript
// app/layout.tsx
async function RootLayout({ children }: { children: React.ReactNode }) {
  const user = await getUser() // Fetched once
  return <div>{children}</div>
}

// app/page.tsx
async function Page() {
  const user = await getUser() // ✅ Same request, cached (deduped)
  return <div>{user.name}</div>
}
```

**React automatically deduplicates fetch requests** in Server Components.

**For non-fetch data**, use React `cache()`:

```typescript
import { cache } from 'react'

const getUser = cache(async (id: string) => {
  return db.user.findUnique({ where: { id } })
})
```

## 4. API Routes: Route Handlers

### New Pattern: route.ts

**Replace pages/api/ with app/api/route.ts**:

```typescript
// app/api/posts/route.ts
import { NextRequest, NextResponse } from 'next/server'

export async function GET(request: NextRequest) {
  const posts = await db.post.findMany()
  return NextResponse.json(posts)
}

export async function POST(request: NextRequest) {
  const body = await request.json()
  const post = await db.post.create({ data: body })
  return NextResponse.json(post, { status: 201 })
}
```

**Dynamic routes**:
```typescript
// app/api/posts/[id]/route.ts
export async function GET(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  const post = await db.post.findUnique({ where: { id: params.id } })

  if (!post) {
    return NextResponse.json({ error: 'Not found' }, { status: 404 })
  }

  return NextResponse.json(post)
}

export async function PATCH(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  const body = await request.json()
  const post = await db.post.update({
    where: { id: params.id },
    data: body,
  })
  return NextResponse.json(post)
}

export async function DELETE(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  await db.post.delete({ where: { id: params.id } })
  return NextResponse.json({ success: true })
}
```

### Request Helpers

```typescript
// Reading headers
const headersList = headers()
const authorization = headersList.get('authorization')

// Reading cookies
const cookieStore = cookies()
const token = cookieStore.get('token')

// Search params
const searchParams = request.nextUrl.searchParams
const query = searchParams.get('query')
```

### Streaming Responses

```typescript
// app/api/stream/route.ts
export async function GET() {
  const encoder = new TextEncoder()

  const stream = new ReadableStream({
    async start(controller) {
      for (let i = 0; i < 10; i++) {
        await new Promise(resolve => setTimeout(resolve, 1000))
        controller.enqueue(encoder.encode(`Data ${i}\n`))
      }
      controller.close()
    },
  })

  return new Response(stream, {
    headers: { 'Content-Type': 'text/plain' },
  })
}
```

## 5. Server Actions

### Pattern: Server-Side Mutations Without API Routes

**Server Actions replace many API routes** for mutations.

```typescript
// app/actions.ts
'use server'

import { revalidatePath } from 'next/cache'

export async function createPost(formData: FormData) {
  const title = formData.get('title') as string
  const content = formData.get('content') as string

  const post = await db.post.create({
    data: { title, content },
  })

  revalidatePath('/blog')
  return { success: true, post }
}

export async function deletePost(id: string) {
  await db.post.delete({ where: { id } })
  revalidatePath('/blog')
}
```

**Use in forms** (Client Component):
```typescript
// components/PostForm.tsx
'use client'

import { createPost } from '@/app/actions'
import { useFormState, useFormStatus } from 'react-dom'

export function PostForm() {
  const [state, formAction] = useFormState(createPost, null)

  return (
    <form action={formAction}>
      <input name="title" placeholder="Title" required />
      <textarea name="content" placeholder="Content" required />
      <SubmitButton />
      {state?.success && <p>Post created!</p>}
    </form>
  )
}

function SubmitButton() {
  const { pending } = useFormStatus()
  return (
    <button type="submit" disabled={pending}>
      {pending ? 'Creating...' : 'Create Post'}
    </button>
  )
}
```

**Use programmatically**:
```typescript
'use client'

import { deletePost } from '@/app/actions'
import { useTransition } from 'react'

export function DeleteButton({ postId }: { postId: string }) {
  const [isPending, startTransition] = useTransition()

  return (
    <button
      onClick={() => {
        startTransition(async () => {
          await deletePost(postId)
        })
      }}
      disabled={isPending}
    >
      {isPending ? 'Deleting...' : 'Delete'}
    </button>
  )
}
```

### Benefits of Server Actions

- ✅ No API route boilerplate
- ✅ Progressive enhancement (works without JS)
- ✅ Type-safe (TypeScript inference)
- ✅ Automatic revalidation
- ✅ Built-in pending states

**When to use API routes instead**:
- External clients need the endpoint
- Webhooks from third-party services
- Need full REST API
- GraphQL endpoints

## 6. Data Fetching Patterns

### Static Rendering (Default)

**Routes are rendered at build time** (default behavior):

```typescript
// app/blog/page.tsx
async function BlogPage() {
  const posts = await db.post.findMany() // Fetched at build time

  return (
    <div>
      {posts.map(post => (
        <article key={post.id}>{post.title}</article>
      ))}
    </div>
  )
}
```

**Benefits**: Fast, cacheable, great for SEO.

### Dynamic Rendering

**Force dynamic rendering** when you need request-time data:

```typescript
export const dynamic = 'force-dynamic' // Opt out of static rendering

async function ProfilePage() {
  const user = await getCurrentUser() // Fetched on each request
  return <div>{user.name}</div>
}
```

**Automatic dynamic rendering** when using:
- `cookies()` or `headers()` from `next/headers`
- `searchParams` prop in page component
- Dynamic route with no `generateStaticParams`

### Incremental Static Regeneration (ISR)

**Revalidate static pages** after a time period:

```typescript
// app/blog/[slug]/page.tsx
export const revalidate = 3600 // Revalidate every hour

async function BlogPost({ params }: { params: { slug: string } }) {
  const post = await getPost(params.slug)
  return <article>{post.content}</article>
}
```

**On-demand revalidation**:
```typescript
// app/actions.ts
'use server'

import { revalidatePath, revalidateTag } from 'next/cache'

export async function updatePost(id: string) {
  await db.post.update({ where: { id }, data: { ... } })

  // Revalidate specific path
  revalidatePath('/blog')
  revalidatePath(`/blog/${id}`)

  // Or revalidate by tag
  revalidateTag('posts')
}
```

**Using tags**:
```typescript
async function getPosts() {
  const res = await fetch('https://api.example.com/posts', {
    next: { tags: ['posts'] },
  })
  return res.json()
}
```

### Streaming with Suspense

**Stream parts of page** as they load:

```typescript
// app/dashboard/page.tsx
import { Suspense } from 'react'

export default function DashboardPage() {
  return (
    <div>
      <h1>Dashboard</h1>

      {/* Fast component - renders immediately */}
      <RecentActivity />

      {/* Slow component - streams in when ready */}
      <Suspense fallback={<AnalyticsSkeleton />}>
        <Analytics />
      </Suspense>

      <Suspense fallback={<ChartSkeleton />}>
        <RevenueChart />
      </Suspense>
    </div>
  )
}

// Slow async component
async function Analytics() {
  const data = await fetchAnalytics() // Slow query
  return <div>{/* Render data */}</div>
}
```

**Benefits**:
- User sees content progressively
- Doesn't block fast content
- Better perceived performance

### Loading UI

**Automatic loading states** with `loading.tsx`:

```typescript
// app/dashboard/loading.tsx
export default function Loading() {
  return <DashboardSkeleton />
}
```

This creates a Suspense boundary automatically:
```typescript
<Suspense fallback={<Loading />}>
  <Page />
</Suspense>
```

## 9. Middleware for Edge Functions

### Pattern: Request Interception

**Middleware runs before every request** on the Edge Runtime:

```typescript
// middleware.ts (root of project)
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function middleware(request: NextRequest) {
  // Check authentication
  const token = request.cookies.get('token')

  if (!token && request.nextUrl.pathname.startsWith('/dashboard')) {
    return NextResponse.redirect(new URL('/login', request.url))
  }

  // Add custom header
  const response = NextResponse.next()
  response.headers.set('x-custom-header', 'value')

  return response
}

// Match specific paths
export const config = {
  matcher: [
    '/dashboard/:path*',
    '/api/:path*',
  ],
}
```

### Common Use Cases

**Authentication**:
```typescript
export function middleware(request: NextRequest) {
  const session = request.cookies.get('session')

  if (!session) {
    return NextResponse.redirect(new URL('/login', request.url))
  }

  return NextResponse.next()
}
```

**Localization**:
```typescript
export function middleware(request: NextRequest) {
  const locale = request.cookies.get('locale')?.value || 'en'

  if (!request.nextUrl.pathname.startsWith(`/${locale}`)) {
    return NextResponse.redirect(
      new URL(`/${locale}${request.nextUrl.pathname}`, request.url)
    )
  }
}
```

**Bot detection**:
```typescript
export function middleware(request: NextRequest) {
  const userAgent = request.headers.get('user-agent') || ''
  const isBot = /bot|crawler|spider/i.test(userAgent)

  if (isBot) {
    return NextResponse.rewrite(new URL('/bot-page', request.url))
  }
}
```

**A/B testing**:
```typescript
export function middleware(request: NextRequest) {
  const bucket = request.cookies.get('bucket')?.value || Math.random() < 0.5 ? 'a' : 'b'

  const response = NextResponse.rewrite(new URL(`/experiment/${bucket}`, request.url))
  response.cookies.set('bucket', bucket)

  return response
}
```

### Limitations

**Edge Runtime restrictions**:
- ❌ No Node.js APIs (fs, path, crypto)
- ❌ No native Node modules
- ❌ Limited package compatibility
- ✅ Runs at the edge (low latency)
- ✅ Lightweight functions only

**Check compatibility**: https://edge-runtime.vercel.app/packages

## 10. Performance Optimization Patterns

### Image Optimization

**Use next/image** (automatic optimization):

```typescript
import Image from 'next/image'

export function ProductImage() {
  return (
    <Image
      src="/product.jpg"
```

**Benefits**:

- Lazy loading by default
- Responsive images
- Prevents layout shift

### Font Optimization

**Use next/font** (zero layout shift):

```typescript
// app/layout.tsx
import { Inter, Roboto_Mono } from 'next/font/google'

const inter = Inter({
  subsets: ['latin'],

  variable: '--font-roboto-mono',

  return (
    <html lang="en" className={`${inter.variable} ${robotoMono.variable}`}>
      <body className={inter.className}>{children}</body>
    </html>
  )
}
```

### Script Optimization

**Use next/script** (control loading):

```typescript
import Script from 'next/script'

export function Analytics() {
  return (
    <>
      <Script
        src="https://www.googletagmanager.com/gtag/js"
        strategy="afterInteractive" // Load after page interactive
      />
      <Script id="google-analytics" strategy="afterInteractive">
        {`
          window.dataLayer = window.dataLayer || [];
          function gtag(){dataLayer.push(arguments);}
          gtag('js', new Date());
          gtag('config', 'GA_MEASUREMENT_ID');
        `}
      </Script>
    </>
  )
}
```

**Strategies**:
- `beforeInteractive` - Load before page interactive (critical)
- `afterInteractive` - Load after page interactive (default)
- `lazyOnload` - Load during idle time
- `worker` - Load in web worker (experimental)

## Integration with Architecture Principles

### SRP (Single Responsibility Principle)

**One route, one purpose**:
```typescript
// ✅ Good - focused responsibility
// app/dashboard/analytics/page.tsx
async function AnalyticsPage() {
  const data = await getAnalytics()
  return <AnalyticsDashboard data={data} />
}

// ❌ Bad - multiple responsibilities
// app/dashboard/page.tsx
async function DashboardPage() {
  const analytics = await getAnalytics()
  const users = await getUsers()
  const products = await getProducts()
  const orders = await getOrders()
  // Too much!
}
```

**Use parallel routes** for distinct sections:
```
app/dashboard/
├── @analytics/page.tsx  # Analytics only
├── @users/page.tsx      # Users only
└── layout.tsx           # Compose them
```

### DRY (Don't Repeat Yourself)

**Share layouts** instead of duplicating:
```typescript
// ❌ Bad - duplicated header/footer
// app/about/page.tsx
export default function AboutPage() {
  return (
    <>
      <Header />
      <main>About content</main>
      <Footer />
    </>
  )
}

// ✅ Good - shared layout
// app/(marketing)/layout.tsx
export default function MarketingLayout({ children }) {
  return (
    <>
      <Header />
      <main>{children}</main>
      <Footer />
    </>
  )
}
```

**Use Server Actions** instead of duplicating mutation logic:
```typescript
// ✅ Good - shared server action
'use server'
export async function createPost(data: FormData) {
  // Single source of truth for creating posts
}

// Use in multiple forms
<form action={createPost}>...</form>
```

### YAGNI (You Aren't Gonna Need It)

**Start with static rendering** (default), only opt into dynamic when needed:

```typescript
// ✅ Start here - static by default
export default async function ProductPage() {
  const products = await getProducts()
  return <ProductList products={products} />
}

// ❌ Don't prematurely optimize
export const dynamic = 'force-dynamic' // Only add when you need it!
export const revalidate = 60 // Only add when you need it!
```

**Don't use Client Components** unless you need interactivity:
```typescript
// ✅ Server Component - no JS needed
export function ProductCard({ product }) {
  return <div>{product.name}</div>
}

// ❌ Unnecessary Client Component
'use client' // Why? No interactivity!
export function ProductCard({ product }) {
  return <div>{product.name}</div>
}
```

## Checklist

Before deploying Next.js 14+ app:

- [ ] Most components are Server Components (default)
- [ ] Client Components only where needed ('use client')
- [ ] Server Actions used for mutations (reduce API routes)
- [ ] Images use next/image with proper sizing
- [ ] Fonts use next/font (zero layout shift)
- [ ] Loading states with loading.tsx or Suspense
- [ ] Error boundaries with error.tsx
- [ ] Metadata (static or dynamic) for every page
- [ ] Layouts used for shared UI (not duplicated)
- [ ] Route groups organize related pages
- [ ] ISR used for content that changes (revalidate)
- [ ] Dynamic routes have generateStaticParams
- [ ] Middleware only for edge cases (auth, redirects)
- [ ] Bundle analyzed (no huge dependencies)
- [ ] TypeScript strict mode enabled

## Common Anti-Patterns

| Anti-Pattern | Why Bad | Fix |
|--------------|---------|-----|
| `'use client'` everywhere | Sends unnecessary JS | Only mark interactive components |
| Fetching in Client Components | Waterfalls, loading states | Fetch in Server Components, pass as props |
| Not using layouts | Duplicated UI code | Extract shared UI to layout.tsx |
| API routes for every mutation | Boilerplate, type safety issues | Use Server Actions |
| No loading states | Poor UX during data fetching | Add loading.tsx or Suspense |
| Ignoring ISR | Static data goes stale | Use revalidate or revalidatePath |
| Client-side auth checks | Security risk, flickers | Use middleware |
| Not using next/image | Slow images, layout shift | Replace <img> with <Image> |
| Dynamic everything | Slow builds, unnecessary server load | Start static, opt into dynamic |

## Summary

Next.js 14+ fundamentally shifts to:

1. **Server Components by default** - Zero JS unless you opt in with 'use client'
2. **File-system routing** - Convention over configuration with app/
3. **Layouts > Code duplication** - Share UI through nested layouts
4. **Server Actions > API routes** - Type-safe mutations without boilerplate
5. **Streaming > Waiting** - Progressive rendering with Suspense
6. **Static by default** - Only dynamic when you need it (ISR, force-dynamic)
7. **Edge middleware** - Run auth/redirects at the edge
8. **Built-in optimization** - Images, fonts, scripts optimized automatically

**Core principle**: Server-first with client opt-in. Keep as much on the server as possible, send minimal JS to the client.
